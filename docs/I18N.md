# Languages

The web UI and the messages the API returns are translated. English is the source language; German is
the first translation. Catalogs are [Fluent](https://projectfluent.org/) files in
`crates/patronus-web/i18n/<tag>.ftl`, compiled into `patronus-web` (no files to install, nothing read
at run time except the settings below).

## Which language a request gets

In this order, the first that names a language with a catalog wins:

1. the signed-in account's own language (System > Language, `PUT /api/i18n/me`; stored per account in
   the configuration, so export, backup and GitOps carry it);
2. the choice made on the sign-in page (`/login?lang=de` sets the `patronus_lang` cookie);
3. the system default (`auto` = none): `ui.language` in the configuration store (System > Language or
   `PUT /api/i18n/system`, administrators), else `[ui] language = "de"` in `patronus.toml`, else the
   environment variable `PATRONUS_UI_LANGUAGE`;
4. the browser's `Accept-Language` (`de-AT` uses the `de` catalog; q-values are honoured);
5. English.

`GET /api/i18n` shows what applies to the caller and which languages exist. Responses carry
`Content-Language` and `Vary: Accept-Language, Cookie`; pages carry `<html lang>`.

## Catalog rules

- `nav-*`, `crumb-*`, `login-*`, `lang-*`, `apidocs-*`: text of pages, used in templates as
  `{{ "nav-firewall"|t }}` (other filters: `t_with`, `crumb`, `lang_code`, `lang_links`, `js_catalog`).
- `js-*`: strings the page scripts read with `tr('js-...')` (`window.PATRONUS_I18N`).
- `err-*`: API messages. The English text of the entry is also the lookup key: handlers that still write
  the English message are translated on the way out (`$v1`..`$v9` stand for the variable parts), and new
  code calls `i18n::api_error(status, "err-key", args)`, which also returns the key as `"code"`.
- A key a language lacks falls back to English; `ci/check-i18n.py` refuses a catalog that lacks a key,
  has a key English does not, or changes a variable.

## Adding a language

1. Copy `crates/patronus-web/i18n/en.ftl` to `<tag>.ftl`, translate the values (keep keys and `$variables`).
2. Add one line to `CATALOGS` in `crates/patronus-web/src/i18n.rs`.
3. `python3 ci/check-i18n.py` and `cargo test -p patronus-web`. The language shows up in the pickers by
   its own name (`lang-name`).

## No new hard-coded text

`ci/check-i18n.py` counts visible text in templates and literal API error messages in Rust against
`ci/i18n-baseline.json`; a file may not exceed its baseline (new files: 0). New text goes into the
catalog. `base.html`, `login.html` and `api_docs.html` are fully converted and must stay at 0. Product
names and protocol keywords are marked `i18n-ok` on their line. Converting an old page: replace its
texts with keys, add them to both catalogs, run `python3 ci/check-i18n.py --update` and commit the
lower baseline.
